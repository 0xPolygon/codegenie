# Phase 4: Solidity vertical slice

## Overview

Add first-class Solidity repository context on top of the shared Plan 98 foundation and the Rust/Python slices. This phase replaces the grammar-only Solidity placeholder with a semantic adapter, deterministic default Foundry test discovery, a default-enabled evidence-driven Solidity review skill, structural and fake-transport fixtures, installed-package grammar/skill/parse coverage, and synchronized normative documentation. It deliberately leaves `exported` unset and defers storage-layout/generated-getter/ABI analysis, custom Foundry directories, Hardhat TypeScript linking, native semantic analysis, real-model baselining, and merge/release.

## Steps

1. Add `src/repo/tree-sitter/solidity-adapter.ts` and register it in `LanguageAdapterRegistry`. Extract contract, abstract-contract, library, interface, direct contract functions, constructors, fallback/receive handlers, modifiers, file-level free functions, contract-owned state variables/constants, structs, enums, user-defined value types, events, and custom errors with the exact Plan 98 kind/native-kind/name/immediate-owner contract. Do not emit file-level constants as `value` symbols. Build bounded body-free declaration signatures, retain full declaration ranges for header/body enclosure, select the smallest direct member before its containing contract, leave `exported` unset, and use path/kind/owner/name/range/signature identity so overloads remain distinct.
2. Extract only unquoted Solidity import source paths from plain, namespace-alias, unit-alias, and named-import forms in source order with semantic deduplication.
3. Complete `src/repo/likely-tests.ts` Foundry classification for convention-selected candidates. Resolve `<Stem>.t.sol` and `<Stem>Test.t.sol` only under the nearest `foundry.toml` package's default `test/` directory, return no candidates when that marker is absent, and mark direct contract methods beginning `test` or `invariant` as `nativeKind: "test case"` while excluding `setUp`, free functions, and nested/local declarations. Preserve deterministic sorting/deduplication, the shared 20-result cap, source selection, candidate/body mention gates, parser fallback, backend, and precision metadata. Do not discover custom Foundry directories or Hardhat TypeScript tests.
4. Add `bundled-skills/lang/solidity.md` as a default-enabled Solidity lens skill. Give every required check an observable failure predicate, reachability/materiality and impact-based severity rule, concrete unsafe example, distinct safe counterexample, and separate mitigation; include the required Checks, False Positives, Safe Patterns, and Examples sections. Add evidence-bearing `lang/solidity` entries to `BUNDLED_SKILL_WHY_LEDGER` and pin every owner-matrix field independently, full untruncated projection, total-budget fit, and Solidity-only Stage-7/9 projection.
5. Add a structural Solidity repository fixture and integration assertions covering canonical identity, clean Solidity parsing, all symbol kinds/ranges/owners/signatures/identity, smallest-member header/body enclosure, source-only imports, exact Foundry likely tests and symbols, packet outline/context/lens, and Solidity-only Stage-7/9 skill projection. Add focused malformed/partial, overload, ordering, cap, import, and deferred-behavior coverage where the shared harness does not already pin it.
6. Add `evals/fixtures/repos/solidity/` and `evals/fixtures/solidity.yml` with a feature-side marker case plus a marker-free negative control. Extend the fixture materialization test and inventory documentation from six to seven cases while keeping adapter/symbol/test/lens/skill proof in structural tests rather than candidate expectations.
7. Extend the packed-consumer gate to install the actual published Solidity grammar package with scripts enabled under the repository policy, require `lang/solidity.md` and the compiled Solidity adapter, resolve the grammar WASM from the installed dependency tree, minimally parse Solidity through the production registry, and assert the expected semantic symbol. Record the pnpm/npm dependency and install-script decision evidence already established by the shared foundation; if supported consumer install/runtime breaks, stop and implement the Plan 98 vendored-WASM path rather than weakening the gate.
8. Synchronize README and the normative functional, architecture, repository/context, pipeline, skills/telemetry, eval, and PUNCHLIST documentation for the complete Solidity slice, seven-skill inventory, exact symbol/test contracts, unset `exported`, explicit deferrals, and intermediate unreleased/cache-boundary status.
9. Run focused Solidity and affected regression tests, then complete `pnpm run check`, `pnpm test`, `pnpm build`, installed-package gate, and fake fixture suite. Iterate until every gate passes without establishing an eval baseline or merging/releasing the integration series.

## Tests

- `SolidityAdapter` symbol contract: extracts exact types/interfaces/methods/functions/values/other declarations, immediate contract owners, synthetic constructor/fallback/receive names, explicit native kinds, bounded body-free signatures, deterministic order, and no `exported` values.
- Solidity declaration identity and enclosure: merges multiple changed lines within one declaration, preserves same-named overloads, and binds header/body lines to the smallest direct member before the containing contract.
- Solidity imports: emits only unquoted source paths from every supported import form in first-seen source order with deduplication.
- Solidity test symbols: recognizes only direct contract methods beginning `test` or `invariant` in selected `.t.sol` candidates as `nativeKind: "test case"`; excludes `setUp`, free functions, and ordinary methods.
- Foundry likely tests: requires the nearest `foundry.toml`, maps only that package's default `test/<Stem>.t.sol` and `test/<Stem>Test.t.sol`, prefers a nested nearest marker, sorts/dedupes/caps results, preserves source and symbol filtering, and does not infer custom test directories or Hardhat links.
- Solidity structural integration: carries `solidity` consistently through diff facts, adapter, outline, packet, lens, exact relevant tests, and Solidity-only Stage-7/9 prompt projection on a clean production-path fixture.
- Solidity degradation: malformed partial trees remain bounded and parser-unavailable/throw/timeout paths retain shared degradation semantics without relabeling the requested adapter.
- Solidity skill quality: verifies required sections, every independently parsed owner-matrix field, evidence-bearing WHY ledger, default enablement, caps, and compatible Stage-7/9 projection.
- Solidity fake fixture: positive marker transports and anchors; marker-free negative control yields no finding.
- Packed Solidity layout: a scripts-enabled installed consumer contains the Solidity skill/adapter, resolves the published Solidity grammar WASM, and parses a semantic Solidity declaration through the production registry.
- Full regression suite: existing Go/TypeScript/Rust/Python classification, adapters, packets, relevant tests, and Stage-7/9 skill isolation remain unchanged.
