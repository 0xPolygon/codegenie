# #427 · Development-only eval campaign runner

**Decision.** Put campaign orchestration in `evals/runner/`. A small Python 3 standard-library supervisor owns the schedule, SQLite ledger and receipts. One Node worker per attempt calls the existing built Codegenie eval and review libraries. This reuses the restart-tested parts of the offline workbench while keeping the normal model adapter, prompt construction, tools, Stage 9 scheduler and scorer authoritative. A second review pipeline, patched copies of built modules and a new installed CLI command are out of scope.

## Entry points and data ownership

- From a source checkout after `pnpm install && pnpm build`, use `python3 evals/runner/main.py run --campaign <file>`. Repeating the command resumes the same sealed campaign. A separate `export-blind --campaign <file>` reads terminal receipts without contacting a provider. The ordinary `codegenie eval` interface stays available. No install-time hook or extra runtime dependency.
- A single campaign config identifies case suites, arms and draw order or seed, the provider tuple, caps, checkpoint, planner inputs and output location. Resolve relative paths against the config. Bind the canonical **entire** schedule, case manifest/oracle and tree digests, planner digest per case, build/lockfile, worker, effective arm configs, isolated cache identities and native verifier concurrency. Require a match at startup and restart before health or dispatch. A config may point to external private sources; published examples use public paths only. Runtime roots default outside the checkout. Keep credentials, private paths, raw traces, labels, sheets, maps and receipts outside tracked notes; report aggregates there.
- Ship a working public example under `evals/runner/` and a documented one-command invocation. Given only a normal provider login/key and public network access, it resolves the chosen public case under `evals/public/{repo}/{case}/eval.yml`, prepares a detached checkout of its pinned head and parent in the user cache, and runs it. Reuse the public setup recipes (including PR refs when needed). Validate a pre-existing target's clean tree and pinned objects; never overwrite an unrelated checkout. A bundled fixture proves the same path offline. The oracle and eval expectations stay outside the reviewed directory and model context.
- Keep the current npm `files` allowlist. Keep runner sources outside `src` and `tsconfig.build.json`; use plain Node ESM for the bridge. Extend the existing real `npm pack` test in `tests/package-build.test.ts`: inspect entries of the produced tarball, assert that `evals/runner/` and compiled copies under `dist/evals/runner/` are absent, and retain the positive installed-CLI assertion.

## Review and billing boundary

Use `loadConfig`, `loadEvalSuite` and `runEvalCase`. The last already applies case/repo settings and calls `runReview` with a dedicated artifact directory. Extend internal `EvalRunOptions` only where necessary to direct output to the attempt and forward invocation overrides. Verify the effective provider/model/effort, surface and treatment after config layers, before a physical start. One slot is one draw; do not multiply a case’s existing repeat setting. Disable local response cache or isolate it per case/arm/draw. Shared planner captures enter through a narrow typed override at the existing `runPlanner` call. Check capture, diff and hunk identity before passing the plan to the ordinary Stage 6 builder. Preserve the normal path when no override is supplied.

Resolve credentials through Codegenie’s existing provider configuration and adapter. A run directory is distinct from the authenticated Codegenie home. Do not copy a credential store, read a refresh token, expose credentials to the supervisor, or add OAuth leasing to the repository. #405 needs OpenRouter only. Stored provider accounting is sanitized metadata: call ID, provider/model/purpose, HTTP status, typed terminal classification and provider-reported usage/cost, with explicit unknowns.

For each actual model POST, the worker requests an atomic ledger reservation **immediately before transport**. Count every outbound attempt, including native retries and health probes. An optional observer at the normal adapter/transport boundary may provide this seam; wrapping only `runStructured` or `PiAiAdapter.complete` cannot prove physical cardinality. Settle from native parsed events and physical HTTP status. Keep local refusals and logical model failures separate from this physical ledger (#341). A denied admission creates a typed, non-retryable local record with zero starts. Preserve native estimates separately from confirmed provider cost; a synthetic zero on an error is unconfirmed.

Under a supervisor lock and SQLite transaction, charge open reservations before authorizing dispatch. Enforce the bound dollar or call/token caps across workers, retries and probes. For the first USD campaign retain the qualified OpenRouter policy: $0.40 per open call, $0.05 only for an eligible physical no-usage error, full unknown hold otherwise. At block boundaries and each drained 25-call checkpoint reconcile with fresh whole-key usage. A small unattributed key delta cannot release an unknown hold. A typed local stream abort may retain unknown usage only with matching native reason/event and full hold. Keep partial counters separate from terminal totals. Record a fatal meter or provider denial immediately, including on the last completion. Restart with unmatched starts preserves holds and requires reconciliation.

## Admission, terminal outcomes and blinding

1. Reuse the normal provider path for a minimal health probe. Bind the health result to its slot group, provider, ledger start and terminal evidence. Keep health/freshness state across restart. Resume from a hash-verified **unadmitted** boundary; reuse already valid health at that boundary. A stale reading never implies fresh capacity. A process restart cannot spend a second probe or replay an admitted slot implicitly (#344–#347).
2. Select sealed full or partial product outcomes once. A wrong quality answer or a recovered error does not justify another draw. A qualifying transient physical infrastructure failure may have one authorized retry grounded in a fresh retry-purpose health receipt. A second infrastructure failure seals a slot-level exclusion with both attempt hashes. Health reporting verifies both and retains the other arm’s receipt. Separate a streamed peak-load/request-size refusal from an explicit rate limit, quota, native review budget and pre-dispatch refusal (#348).
3. Apply the standing stop rule at the right boundary. Stop on a missing terminal packet submit, harness exception, internal/timeout/unknown tool error or missing code on a failed tool row, missing required telemetry/usage, and provider 401/402/429 or typed quota denial. The typed local-abort exception above preserves conservative billing. Record documented typed client errors, budget refusals, recovered schema failures, successful retries, and optional location-clarification failures. Count accepted incomplete packets as partial. Do not reconstruct model arguments or require successful optional calls for a packet to count. Independent coverage checks still match expected packet IDs and physical/native records.
4. Seal attempt artifacts and the selected/excluded pointer atomically, with digests verified on reopening. Preserve prior attempts; never pick by quality. Fail closed on contradictory state. Export only receipt-selected attempts, using an opaque keyed ID per attempt and a separately protected mapping. Blind sheets carry case, completeness, neutral source/oracle locators, discovery, promotion, verdicts, and visible findings/summary/questions. Remove arm/provider/order/draw/tool/template, operational statistics, source-path leaks and treatment-only fields. Sort by case and opaque ID. For #405, keep `assignedEffects` out of the first lock; expose it in a separate mechanism export only after both independent grade locks and reconciliation.

## PR order and proof

1. **Public entry and package boundary.** Run one public fixture via built Codegenie and verify the actual tarball. Show that config/credential resolution uses normal product behavior and a private path supplied in a scratch config does not enter the checkout.
2. **Ledger, transport and restart.** Port only the necessary tested logic. Use synthetic transport to exercise a raw retry, pre-start refusal, HTTP-200 typed peak-load error, denied provider, unknown usage, stale meter, parallel reservations and an interrupted/excluded attempt. Assert physical counts, stop persistence, bounds and idempotence. Preserve native Stage 9 concurrency.
3. **Selection, export and #405 qualification.** Test missing packet submit vs optional clarification, partials, blind leakage, receipt drift and suffix-schedule tampering. On the reviewed treatment build, run the sealed 80-slot schedule offline, pause after the first two cases (eight terminal slots) before case-three health, then resume from the bound release with zero duplicate starts. Test exclusion and $15 cap separately; an incomplete allocation is descriptive. First measured use follows operator dispatch authorization.

The existing CLI, provider contracts and frozen corpus are integration dependencies. Synthetic workbench success is evidence for its individual behaviors. Acceptance for #405 requires the checked-in command, reviewed treatment build and real schedule to pass together.
