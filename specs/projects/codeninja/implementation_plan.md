# Implementation Plan: codeninja

Build order follows the architecture's tracer-bullet directive: stand up the minimal end-to-end review path before any optional machinery. Phase 5 runs the whole pipeline against the fake runner (zero API spend); Phase 6 is the milestone where `codeninja review` produces a real review on stdout. Details live in `architecture.md` and `components/*.md` — this file is the ordered checklist.

## Phases

- [x] Phase 1: Scaffold and foundation — pnpm/TS/ESM project, `commander` CLI with `review` command flags and mutual-exclusion rules, `~/.codeninja/` path resolution (`CODENINJA_HOME`), config loader (TOML, zod, full precedence chain including the user-level `config.toml` layer, trust partitioning), typed `CodeninjaError`s, logger + telemetry recorder + run-artifact writers (run dir, `run.log`, `events.jsonl`, `model-calls.jsonl`/`tool-calls.jsonl` + summaries, `.gitignore` provisioning, `retainRuns` pruning, credential stripping). → `components/skills_llm_telemetry.md` (telemetry half)
- [x] Phase 2: Git layer and change inventory — `GitClient` subprocess chokepoint, input resolver for branch/commit modes plus bare default (PR mode deferred to Phase 7), diff parser (hunk ids, line mapping, statuses), anchor index + `validateDiffAnchor` (consumed by Stage 7 output validation and Stage 9 pre-gates), shared detector library + Stage 2 detect/filter pass + Stage 3 classification of kept files. → `components/repository_and_github.md`
- [ ] Phase 3: Repository intelligence — tree-sitter service (WASM, grammar routing), Go/TS/JS/generic language adapters, Stage 4 changed-symbol extraction, the two v1 static-signal rules, path-containment chokepoint, all nine repository tools with revision reads and the ripgrep fast path, `PacketContext` assembly; verify the pinned web-tree-sitter version exposes a parse-timeout mechanism and that grammar wasm ships in the pinned tarballs (crit-verified once; re-verify at pin time). → `components/context_and_tools.md`
- [ ] Phase 4: Skills, provider auth, and LLM runner — `codeninja provider` command namespace, Pi provider/model registry integration, login/logout/auth-status/models/config commands, user-level provider/model/depth/reasoning defaults (`settings.json` joining the Phase 1 loader as a source), skill loader, lens registry, prompt builder with projection maps and untrusted-content fencing, pi-runner (submit-tool structured outputs, TypeBox schemas, tool loop, budgets, abort timeouts, backoff, single provider/model/reasoning resolution), fake `LlmRunner` and fake provider registry for tests, author the four bundled skills against the content outlines in `components/skills_llm_telemetry.md`; verify the Pi auth/model-registry surface (PiAuthStorage/PiModelRegistry, OAuth/device flows, cost reporting) at phase start — provider CLI scope is contingent on it. → `components/skills_llm_telemetry.md`
- [ ] Phase 5: Pipeline spine on the fake runner — orchestrator (`runReview`) with the eval entrypoint overrides (explicit repo root + run-artifact dir), planner dossier, planner output validation + deterministic fallbacks, packet builder, worker runner, Stage 7/9/10 flows, Markdown/JSON renderers, budget ladder + `RunCoverageStatus` + zero-work short-circuit — all exercised end to end against the fake `LlmRunner`. Milestone: a complete deterministic fake review on stdout with zero API spend; every stage artifact written. → `components/review_pipeline.md`
- [ ] Phase 6: Live review — real planner, packet-review, verifier, and composer calls through the pi-runner; schema-repair and backoff behavior against real providers; prompt tuning; follow-up hints surfaced as needs-human-attention notes. Milestone: `codeninja review --branch X` produces a real review end to end. Stage 8 stays deferred. → `components/review_pipeline.md` + `components/skills_llm_telemetry.md`
- [ ] Phase 7: GitHub integration — `GitHubClient`, `--pr` mode (ref fetching, fork PRs, shallow handling), pre-posting anchor validation against the GitHub-matched diff, own-comment listing for duplicate detection, publishing (single `COMMENT` review, 422 recovery, comment sanitization), `--post-github-comments`. → `components/repository_and_github.md`
- [ ] Phase 8: Model-call cache — normalized-request keys, per-call loop caching, integrity checks, eviction, `--cache`/`--no-cache`. → `components/skills_llm_telemetry.md`
- [ ] Phase 9: Evals — `codeninja eval` command, YAML case loading, expectation matching with coarse loss attribution, `--from-artifacts` re-scoring, compare-to-previous, plus a starter fixture-based eval suite that runs in CI; the seed eval suite must cover each bundled lens (core, tests, go, typescript). → `components/evals.md`
