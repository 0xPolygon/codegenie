# A repository tool set for finding and verifying bugs in changes

Joint proposal by architect and architect-2 for #280, the lane B design under #252. The two independent designs were locked before exchange. The proposal applies to the CLI and Action reviewing pinned base-to-head changes. All evidence below comes from offline source and trace reads.

## Decision

Give the reviewer and verifier six operations: **read_change, read_range, read_definition, find_usages, search_files, list_files**. Four answer different evidence questions: what changed, what the source says, where a name is defined, and where it is used. Text and path searches handle the cases where a reviewer has no symbol or does not know the file. Two independent designs arrived at essentially these capabilities with four versus six names. We chose six to keep a path listing distinct from a content search and a definition body distinct from its uses. Both stages use the same evidence semantics.

The strongest opportunity is preserving a route to the *other* piece of evidence. On cg-10, one reviewer lost two intervening writes at a truncation boundary. Another got all four writes in its own conversation and still missed the failure. Improving delivery can fix the first problem. Only a measured comparison can show an improvement in the second.

### The surface

All paths are repository relative. Reads default to head and display the actual revision prominently; 87% of historical range calls omitted the side. Explicit base reads do not fall through to head. Below, a cursor is optional for any paged operation. Day counts are rough estimates by architect-2 for work above the separately reviewed lane A corrections, including focused fixtures. **Stage 7** starts with its changed lines, change directory and omission boundaries. **Stage 9** starts with the candidate, cited locations and the fact it needs to verify; it can request the directory. Its next read should establish or refute that fact. Verifiers cite read_range paths in 938/1,168 eligible results versus 585/3,340 at discovery. Citations are a measure of use; they do not establish correctness. In the experiment preserve today's stage, lens, packet eligibility and budgets, including submit-only packets. For a packet already allowed to ask about symbol occurrences, test filtering is a scope on the same operation. Record any change to effective access as a treatment exposure. Document zero-tool anchors separately. No worker gains another worker's private reasoning.

## Shared contracts and implementation order

1. Finish lane A on the existing nine. The replay criterion there is byte identity for correct, fully delivered results. Lane B deliberately changes display and schemas; its offline criterion is preservation of evidence, revision, scope and usable anchors.
2. Build the pinned path/hunk directory and one numbered diff renderer shared with arm E. Compare base and head independently. When a declaration crosses changed ranges, widen using both trees and keep unchanged lines once. If either enclosing symbol is missing, ambiguous or unsupported, return the available hunk/ranges with that limitation. An explicitly selected unchanged range can always be read separately on either side. Do not infer equivalence between similarly named definitions.
3. Add the six model descriptors in src/llm/tool-definitions.ts and implement their selectors in src/repo/repository-index.ts, src/repo/diff-blocks.ts, src/repo/search.ts and the existing symbol/test helpers. Use src/llm/search-result-packing.ts and pi-runner's current post-cache budget enforcement. Key caches/cursors on revision pair, query/selector, mode and scope. A changed selector, wrong revision or stale cursor returns an error before reading. Retain historical tool names for decoding stored traces and keep stage submission schemas separate.
4. Every response identifies its revision and actual scope. Distinguish no match, missing file, ambiguous, unsupported, invalid arguments, incomplete scan, partial delivery and budget refusal. Report exact omissions only when known. Return whole rows/lines with a resume position. For an individual oversized line or row, report its position and provide a bounded column window or location-only entry. If even that cannot fit, return a typed budget refusal. A cursor must start with the first undelivered item in a deterministic order. Cover renames/deletions, syntax recovery, shadowing and dotted names, empty scopes, overlarge hunks and cache-hit repacking on all three repos. Keep budget and elapsed costs visible even on error.

## Measurement and ship decision

**Offline first.** Replay the table's calls at baseline and treatment pins, including the actual next request of the same worker. Check that a resumed read returns cg-10 lines 324 onward; cg-01's directory exposes the deleted pi-runner hunk; cg-04's page contains the skipped matching locations; both dotted uses in go-01 are recoverable; and a test-scoped query for an actual parser or SDK symbol returns the source line in the test. Where a test exercises a symbol only transitively, label the available evidence precisely. Record bytes/calls needed to reach the decisive location. Replay successful reads of reliable cases too. A result which already delivered the decisive source is counted once.

**When the operator lifts the hold**, run three paired Luna-high arms: lane A corrections with the current prompt, E with those same tools, and E with the six tools. The last pair isolates the tool surface. Pin every manifest/tree, model, budget, Stage 5 capture and stage selection. Keep the packet contents constant apart from the registered presentation and directory exposure; use counterbalanced order and two draws per case. For verification, replay identical captured candidate and promotion inputs through the two verifier tool surfaces with fixed composition. Preserve both direct candidates and scoped questions. Distinguish first source delivery, Stage 7 raise, promotion, verifier gate suppression, investigated verdict, reader-visible question and publication.

Use one vote per diff. Blind source adjudicators to arm, including on controls. Report exact findings and precise external-fact questions separately; an external question must name the local changed behavior, missing external premise and possible consequence. Count it only for the preregistered external stratum. Track the eight hard targets individually and protect go-04, pi-01, pi-05, pi-06, go-08, go-02, pi-10, cg-10 primitive rejection and go-09. Keep held-out/mixed cases and contaminated controls on separate lines. Include cg-08 and the newly added cases so gains on the known targets cannot hide a regression.

Proposed recall screen: at least two of the eight newly raised in both draws compared with E alone, a source-supported gain in publication or in the separately declared external-question endpoint, no reliably found cause lost in both draws, no increase in Stage 7 repairs or surviving medium-or-higher false control claims at equal exposure. Four such control claims per historical arm is a reference; compare matched clean-control denominators. Report rejected/refused calls per packet, repeated reads, usable evidence per character, source coverage, Stage 9 false proof and p50/p90 wall time and priced/unpriced cost. An efficiency-only gain can justify a separate usability decision but cannot be called a recall win. If the bundle passes, ablate test discovery separately.
