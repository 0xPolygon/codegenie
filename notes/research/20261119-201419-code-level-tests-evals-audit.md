## What the evals can measure

- **Deterministic harness behavior.** The eight public fake-runner fixtures test transport, anchored publication and lens wiring. The synthetic scenarios exercise repository tools and successive GitHub comment publication through scripted boundaries. The language skill suite has confirmed regression/negative controls using real languages and opt-in, three-draw hosted-model YAML. None of these establish precision or model quality on varied real PRs. - **Labeled signal.** Positive assignment, must-not-find patterns, candidate versus final recall, human-attention-only surfacing, stage-loss attribution, and optional completeness, recovery, prompt and budget checks are useful on frozen labeled cases. Repeats require no local model cache and run sequentially on the same materialized repo. This yields empirical hit counts, including failures in the denominator. It does not freeze moving refs between repeated invocations, quantify uncertainty, compare cohorts or provide general precision. Unknown findings can be true positives. The recommendation judge is separately rubric-based and verifies quotes and labels; it is an observational metric and does not change deterministic pass/fail. Calibrate it against independently adjudicated correct, wrong and withheld recommendations before relying on a provider comparison. - **Comparability gap.** Single-run “previous” selects by case name and directory number, even across different case hashes or effective settings. Repeat aggregates have no equivalent comparison, and effective config in `info.json` covers only a subset of tuning and provenance. Use an explicit baseline selection and the existing captured case hash, resolved revisions, runtime, model and config as the comparability contract. Repeated arms should be interleaved when provider load matters. Report per-case material candidate/report rates, successful run denominators, explicitly adjudicated new false positives, uncertainty/withheld rates, cost and elapsed distribution.
