# Model compatibility, stage economics and a fast review lane

Reviewed master `f240376`, codegenie 0.8.0, pi-ai 1.5.2. The immediate fixes are a broken default submit request for current Claude models and disagreement between credential preflight and Pi. For speed, benchmark the existing light depth first. It already limits the stage that consumes most tokens and retains independent verification. No paid model runs were made.

## What crosses the provider boundary

One `createPiRunner` resolves one model, validates the configured reasoning, owns the concurrency limiter, recovery obligations and call-ID sequence, and serves the pipeline via `runStructured`. Stages 5, 7, 8, 9 and 10 request a typed result. The ordinary path uses Pi's `Models.streamSimple`. The forced path uses `Models.stream` with codegenie's own tool-choice and reasoning translations. Both consume Pi's public events. Local replay keys already include provider, model, route, reasoning, stage, schema, tools and conversation. Creating a runner per stage would duplicate IDs, recovery state and limiters. Sources: `src/llm/pi-runner.ts:208–265,974–1021,1791–1842`, `src/pipeline/review-runner.ts:205–280`, `src/review-stages.ts:11–24`, `package.json:31`.

### 1. Current Claude models receive a documented invalid submit request

The preferred model after Anthropic login uses the same provider-scoped query. The README's concrete Opus 5 result is stale. Offline Pi payload capture for Opus 5.5 and Fable 5.2 showed named choice plus adaptive thinking. The runner's assertion that thinking is off disagrees with this request. Pi honors the models' inability to turn thinking off. Anthropic documents HTTP 400 for named choice on both. The vendor date for Opus 5.5 is September 22, 2026 and Fable 5.2 launched November 9, 2026. The initial result came from a local serialization capture and the published endpoint contract. Subsequent owner-authorized live token counts confirmed both model rejections and the successful automatic controls. ### 2. Preflight can refuse credentials Pi supports

**Verified code bug.** With an empty codegenie store and only a fixture `ANTHROPIC_AUTH_TOKEN`, the installed `builtinModels().checkAuth("anthropic")` succeeded and codegenie's real `resolveModel` returned undefined. Pi supports bearer headers and workload identity federation. Codegenie's synchronous preflight checks a copied API-key table and selected ambient special cases. Testing that every provider has a row cannot establish that all credentials for that provider work. Keep the small mapping needed to *place* an explicit GitHub Action key and describe it to a workflow author. For normal preflight, use Pi's async `checkAuth` without refreshing OAuth, with the same credential store and environment as dispatch. Preserve explicit model errors and automatic selection order. Measure the paths end to end with fixture bearer, stored key/OAuth and both supported ambient cloud setups. Sources: `src/provider/pi-ai-models.ts:9–17,58–69,111–145`, `src/provider/provider-services.ts:209–228`, `src/llm/pi-runner.ts:4197–4222,4289–4306`, `tests/model-resolution.test.ts:40–56`; pi-ai 1.5.2 `dist/models.d.ts:169–187`, `dist/providers/anthropic.js:16–57`.

The Action's collision guard is necessary: in an adapter-only test with a stored fixture key plus a routed fixture key, the SDK sent the stored one. The full Action checks for this collision and stops before dispatch. Its configured aliases are workflow-owned, named case-insensitively after permission checks, and cannot select an arbitrary model from a comment. A mixed-provider generic key is rejected if the required env-var names differ. CLI fuzzy selection has a separate interactive contract and persists the exact result. These paths can share suffix parsing, as they already do. Making Action aliases fuzzy would change their trust boundary. The functional spec's promise that native env vars are never overwritten is stale. ### 4. Preserve the parts of submission repair that buy signal

The stage submit requires a start/delta/end sequence, matching IDs/names, full-object parsing with at most Pi's narrow string repair, and deep equality with both event-end and terminal arguments. A length stop is rejected. Repository tool calls use Pi validation separately. On Gemini the SDK emits the delta by serializing the provider's structured arguments; “strict” therefore describes the Pi event path, not independent proof about bytes on the provider wire. Current Pi's `argumentsError` detects malformed text on supported parsers, but a successful terminal `arguments` alone cannot distinguish strict from repaired, a missing event, a diverging end event, or a length stop. Deleting the accumulator today would lose those protections and diagnostics. Sources: `src/llm/final-tool-arguments.ts:52–107,121–134,193–235`, `src/llm/pi-runner.ts:2169,2676`, pi-ai `dist/utils/json-parse.js:83–105`, `dist/api/google-generative-ai.js:143–158`, plan 112 lines 69–74.

Untrusted submissions trigger regeneration using trusted context. A readable invalid draft can receive deterministic cleanup or constrained field updates, and a draft containing candidates cannot silently become clean via repair. A worker restart carries unresolved draft obligations. The shared runner permits up to three schema repairs subject to one repair deadline, while location clarification gets none. Ordinary calls permit four provider attempts, with 429/5xx handling and SDK retries disabled. Repairs, composition and clarification have one inner attempt. Composition has two primary attempts, each capped at 300 seconds, plus a shared repair allowance. The top-level specs prescribing one schema retry are stale. Keep these distinct failure modes in tests. Simplify field requirements only with replay of the original invalid draft, corrected output and retained evidence; stop if a candidate, verdict or source reference silently disappears. Sources: `src/llm/pi-runner.ts:177–181,324–351,375–384,418–422,582–622,1265–1316,1474,1564,3715–3746`, `specs/project/functional_spec.md:400`, `specs/project/architecture.md:1367`, plan 124 lines 23–29,134–139.

## Backlog verdicts

**#29 — valid, premise partly stale; defer public stage configuration until a measured use case.** One global model still serves every stage. Reasoning already varies by call: repair and location clarification use the lowest supported level, the composer normally steps down one model-supported level, and forced Anthropic can override thinking. The project's “same reasoning for all roles” is stale. A cheap structural stage is an economic hypothesis; A shows a small absolute dollar opportunity but large serial planner latency. For an experimental comparison, resolve the chosen model once per distinct user-scoped stage selection inside the existing runner, choose at `runStructured(request.stage)`, and hold it for every continuation/repair of that request. Preserve one run-level limiter, ID sequence, budget ledger and recovery map. Account for location clarification, and record the selected model/route per call. Preflight all selected credentials/levels and preserve Action alias/credential constraints before any user-facing mixed-provider support. Reject a public configuration matrix if it cannot beat simpler global-model or light-depth comparisons while retaining signal. Historical plan 29 concerns *tool budget extensions*, a different subject from GitHub #29. **#31 — valid, independent gate requirement; do not use planner skips to manufacture fast-lane savings.** A reasoned planner skip survives normalization and is excluded before packet construction. The final ledger counts it together with deterministic filters; partial planning already changes how a skip counts towards exclusions. Per-hunk planner decisions and events can be inspected, while the public unreviewed-by-path detail omits both classes of deliberate skip. There is no prohibition option. CLI sets nonzero for failed health; incomplete budget-limited coverage by itself is insufficient. A strict opt-in needs both pieces: convert model skips to the existing non-skip default at normalization before packet construction, and fail the strict gate if any deterministically eligible hunk lacks a completed required packet result. Reuse one final gate decision for CLI and Action, retain partial artifacts, and validate exact eligible hunk IDs rather than only aggregate arithmetic. Preserve the current default. Cases: legitimate generated/path skips, reasoned/empty planner skips, duplicate or absent planned decisions, required-packet failure/timeout, budget stop, zero eligible hunks. Clarify with owner whether verification or unresolved attention independently fails the gate; the issue's coverage guarantee addresses completed packet review and cannot promise a model read every line faithfully.
