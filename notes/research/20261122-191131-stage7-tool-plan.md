# Stage 7 and Stage 9 repository tools: consolidated plan

**Keep the nine repository tools and fix them in two lanes. Corrections to results that are false, empty, cut without a position or mislabelled merge one ticket at a time on review. Changes to how a working call reads ship as one tool surface and are measured with the Stage 7 prompt work.**

Tracker: #252, with #251 and #253 to #261 as the per-tool tickets.


Baseline: v0.9.1 (`7b0b4bc`); the tool code is unchanged on master `2002632`. Evidence: 9,331 model tool calls in the sealed plan 132 ledgers (Stage 7: 6,926; Stage 9: 2,405), replayed against each case's pinned tree. No model calls.

## Decision

Keep the nine tools for now and fix them in two lanes.

- **Lane A, corrections.** A result that is false, empty, cut without a position, or mislabelled becomes true and complete. Results that are already correct and fully delivered stay byte-identical. Each fix is its own PR and merges on exact-head review after unit tests on real fixtures and a before/after replay of the stored calls.
- **Lane B, surface.** New or removed parameters and tools, rewritten descriptions, and any change to how a successful, complete result reads. These ship together as one tool surface and are measured with arm E, per the owner's order.

The test for which lane a change belongs in: would a call that works today return different text? If yes, it is lane B.

## Shared rules (the contract every tool result follows)

These come from the same defect appearing in several tools. Each rule names the tickets it settles.

1. **A cut result says what was delivered and how to get the rest.** A resume line, a list of omitted ids, or an instruction to narrow. (#259 R1, R3; #260 D2; #261 O3; #253; #254)
2. **A cut never removes the status footer and never splits a record.** Today five tools fall through to `fitToolResultText` (`src/llm/pi-runner.ts:2466-2477`), which slices the tail, where `withMeta` put the footer (`src/llm/tool-definitions.ts:338`). (#259 R1; #255 unterminated JSON; read_symbol recovery hint)
3. **No empty success for something that exists.** (#260 D1 oversized hunk; #257 dotted names; #259 R4 read past end of file)
4. **`found` means verified.** A text match in an unparsed file is a lead, with `lookupStatus: unavailable`. (#256)
5. **`degraded` means the backend fell back; a bounded delivery is `truncated` with a reason.** Every degraded or truncated row carries a reason. Rows without one today: outline 117, search 91, list_files 35. (#261 T3; #253; #254)
6. **A refusal is recorded as a refusal.** No backend or precision on a call that never ran (`pi-runner.ts:2336`). (T5)
7. **Telemetry records the selector the model sent.** (#260 D4)

## Lane A: ordered steps

### A0. One packer for text results (new, prerequisite for #259, #260, #255, #258)

Five tools fall through to the same cut today: read_range, read_diff_blocks, read_symbol, find_likely_tests and find_definition. Build the packer once. Four tickets depend on it (#259, #260, #255, #258); find_definition (#256) can adopt it afterwards.

- File: `src/llm/search-result-packing.ts`. Add `packTextToolResult(input: ToolExecutionResult, allowance: number): ToolExecutionResult`.
- `ToolExecutionResult` (`src/llm/llm-runner.ts:28-40`) gains optional `packable?: { open: string; records: string[]; separator: string; close: string }`. The uncut text is `open + records.join(separator) + close`, followed by the footer rendered from `meta`. Tools that set it are packed by the new function; tools that do not keep today's path.
  - read_range: one record per line, separator "\n", empty open and close.
  - read_diff_blocks: one record per hunk block, separator "\n\n".
  - find_likely_tests: one record per SymbolRef, serialized so that the uncut text equals today's `JSON.stringify(tests, null, 2)` (open "[\n", separator ",\n", close "\n]", each record indented two spaces). A cut therefore always leaves a valid array. This is the point lead-dev raised: cutting that JSON by lines would split a record.
- `ToolResultMeta` (`src/types.ts:345`) gains optional `totalLines?: number` and `deliveredLineRange?: [number, number]`.
- Behaviour: if the uncut text plus footer fits, return the input unchanged. Otherwise keep the longest prefix of whole records that fits with `close` and the footer, set `truncated`, `deliveryStatus: "truncated"`, `degradationReason: "tool_result_budget"`, update `deliveredLineRange`, and render the footer. If not even one record fits, return the existing budget refusal text, never an empty success.
- Runner: in `pi-runner.ts:917-937`, route results with `packable` to `packTextToolResult` before the `fitToolResultText` fallback.
- Move `withMeta` (`tool-definitions.ts:307-339`) to a module both files can import; its output for an uncut result must not change.
- Tests: `tests/text-tool-contracts.test.ts`. (1) a result that fits is byte-identical to today; (2) a cut result ends on a whole line and still carries the footer; (3) allowance smaller than one line gives a refusal; (4) a cache hit is repacked against the current allowance.

### The replay every PR runs

One script, the one lead-dev-2 already wrote (`tool-symbol-replay-lead2.mjs`), extended to all nine tools: re-execute each stored call's arguments against the pinned facade at the base commit and at the PR head, pack at the stored allowance, and diff status, lookup, delivery and text. A PR passes when its named reproductions change as specified and every previously full, correct delivery is byte-identical. For a result that was already cut, the new content must be a prefix of the old content, shorter by no more than the added footer text. Owner: lead-dev-2 extends it; each PR author runs it.

## Lane B: the tool surface to measure with arm E

One change set, one template and tool-surface version.

1. **Changed-files list in the Stage 7 prompt.** Path, hunk ids, added and removed line counts, and which hunks are in this packet. Reviewers call read_diff_blocks for another changed file 302 times and guess paths that are not in the diff 12 times; pr-summary gives counts only. This is the cheapest joint view for T9 and belongs with P1.
2. **read_range: numbered lines and a first-line header.** `path@head lines A-B of N`.
3. **read_diff_blocks: optional `hunkId`, drop `packetId`, one renderer shared with the packet.** 7 of 13 packetId calls failed because other packets' ids are never shown.
4. **read_file_outline: one text line per symbol and optional `startLine`.** 72 chars per symbol at the median against 328 today, so 4.5 times more of the file fits in the same cap.
5. **search_files: `patternMode: "literal" | "ere"` and a continuation cursor** (lead-dev's design).
6. **find_symbol_mentions: say it returns identifier occurrences, not callers.**
7. **One removal candidate: find_likely_tests.** 46 of 78 calls returned nothing, 19 of the 32 non-empty results were clipped, and two of three precision checks returned nothing where tests exist. Removal is tested as a separate experiment after its delivery is corrected (#255), not decided from usage numbers. read_symbol stays: it overlaps find_definition, but its results are cited in a later submission at the highest rate of any tool at Stage 7 (32 of 98, against 13% to 24% for the others), so there is no case for removing it.
8. **Descriptions and argument shapes (reviewer's review).**
   - Keep `source` as the nested object on every tool. The four invalid calls sent `source: "head"` and were told only "source: invalid". Add a JSON example to the property description and make the error name the expected shape. No string alias.
   - Put selector rules in the provider-facing schema where the provider allows it, and keep the runtime checks: read_symbol needs exactly one of `symbolName` or `line` (`tool-definitions.ts:86-99`), read_diff_blocks exactly one selector (`:141-152`), and find_likely_tests accepts `{}` though its executor rejects it (`repository-index.ts:656-658`).
   - search_files: the 83 invalid expressions are source fragments such as `toLlmError(`; the literal mode in item 5 is the fix.

## Rejected

- **A callers tool.** Real caller resolution needs per-language semantic analysis. find_symbol_mentions with symbol context is the bounded approximation; describe it honestly instead.
- **A raw tree-sitter query tool.** Models already send invalid search syntax in 6% of search calls; nothing in the misses needed a query the existing tools cannot express.
- **Dependency sources (H9).** A CI checkout has no installed dependencies; exposing them adds an install step and a second trust boundary for four cases. Score a precise question as success for that class and revisit after the fixed harness is measured.
- **list_files at base.** The changed-files list covers deleted paths.
- **Raising caps.** The character budget is what binds (43 of 284 normal packets had a call refused, none reached the call limit), but go-01's miss was a scope choice no cap would fix. Measure duplicate reads after lane A, then decide under H5.
- **Putting the footer first in lane A.** It would fix R1 but changes every result's text, so it is lane B (item 2).

## Risks and gaps

- A0 changes the path every text tool result takes. The byte-identical replay on full deliveries is the guard; without it a formatting slip changes thousands of results.
- Lane A and lane B both touch result text. Arm E must branch after lane A merges, or its comparison mixes the two.
- Usefulness has two proxies and neither is causal. lead-dev's: the next response reads a returned path. architect-2's scorecard: a later model submission recorded with call status ok cites a returned path or line (it does not show that the cited field survived validation or publication, and the same file may already have been in the packet). On the second, every tool sits between 13% and 33% at Stage 7, so citation rates do not separate useful tools from useless ones. The scorecard is a local campaign artefact (SHA-256 `1be5e0bc84163334ca0ca4d8d25442f56b041283f423760fd1cf8c51e1e7ddd4`), not tracked here.
- I did not check Stage 9's 6,000-char single-result cap (`src/pipeline/verifier.ts:47`) against the same fixtures. Owner: whoever takes #259.
- 13 stored read_diff_blocks calls cannot be replayed because the selector was not recorded.
